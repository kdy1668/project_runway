# AI 도구 검증 기록

도구와 사용 목적이 확정된 뒤 검증 계획과 결과를 기록한다.

## 공통 검증 원칙

- 검증은 AI 도구의 응답이 아니라 실제 저장소 상태와 실행 결과를 기준으로 판단한다.
- 변경한 영역의 자동 테스트, 빌드와 정적 검사를 우선하고 자동 검증이 없을 때만 확인 가능한 수동 절차로 보완한다.
- 단위 테스트, 통합 테스트, UI Smoke Test와 수동 확인은 서로 대체 관계로 과장하지 않고 실제 확인 범위를 구분한다.
- 테스트를 통과시키기 위해 기존 검증을 삭제하거나 범위를 임의로 줄이지 않는다.
- 실패한 검증과 실행하지 못한 검증을 숨기지 않고 원인, 영향과 후속 확인 항목을 남긴다.
- 검증 뒤 코드나 문서를 수정했으면 영향을 받는 검증을 다시 수행한다.
- 완료 보고 전 diff와 새 파일을 확인하고 불필요한 생성물, 디버깅 코드와 인증정보 노출 여부를 점검한다.

## 결과 상태

| 상태 | 의미 |
| --- | --- |
| 통과 | 명시한 절차를 실행했고 기대 결과를 확인함 |
| 실패 | 절차를 실행했지만 기대 결과를 충족하지 못함 |
| 미실행 | 필요한 검증을 실행하지 않았으며 완료로 간주할 수 없음 |
| 해당 없음 | 변경 범위와 무관하며 그 이유를 설명할 수 있음 |

검증 기록에는 대상과 목적, 사용한 명령 또는 절차, 기대 결과, 실제 결과, 증거 위치, 실패·제약과 미검증 범위를 남긴다. 도구별 세부 통과 기준은 해당 도구의 설치와 활용 범위를 검증한 뒤 추가한다.

## 도구별 검증 기록 항목

- 검증 대상과 목적
- 선행 조건과 사용한 버전
- 실행 절차와 기대 결과
- 실제 결과와 증거 위치
- 실패·제약·미검증 항목
- 후속 의사결정

구체적인 테스트 종류, CI 연동과 자동 실행 범위가 아직 확정되지 않았으므로 현재는 도구별 설정이나 세부 통과 기준을 만들지 않는다.
