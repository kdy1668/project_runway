# 개발용 AI 도구 운영

개발과 검증을 돕는 AI 도구의 조사 결과, 적용 조건과 검증 기록을 관리한다. 이 영역은 RunWay 서비스 내부의 AI 모델·에이전트·오케스트레이션 설계와 분리한다.

## 공통 개발 흐름

개발 순서와 완료 기준은 RunWay가 정의하고, 개별 AI 도구는 필요한 단계만 보조한다.

1. **업무 확인**: Jira의 범위·완료 조건·담당자·상태와 현재 브랜치·기존 변경을 확인한다.
2. **기준 확인**: 요구사항, API, 데이터 모델, ADR과 변경 영역의 개발 문서를 확인한다. 충돌하거나 미확정인 내용은 구현 전에 구분한다.
3. **작업 계획**: 변경 범위, 영향받는 공통 계약, 예상 파일과 검증 방법을 정한다. API·DB·인증·환경변수·CI 변경은 먼저 영향과 합의 여부를 확인한다.
4. **구현**: 확정된 범위 안에서 필요한 최소 변경을 수행하고 다른 작업자의 변경과 범위 밖 문제를 섞지 않는다.
5. **검증**: 변경 영역의 테스트·빌드·정적 검사 또는 가능한 수동 검증을 수행한다. 모바일 사용자 흐름은 Maestro MCP 검증 후보지만 다른 테스트를 대체하지 않는다.
6. **자체 검토**: Jira 완료 조건, diff, 새 파일, 불필요한 변경과 인증정보 노출 여부를 다시 확인한다.
7. **결과 보고**: 변경 내용, 통과·실패한 검증, 실행하지 못한 검증과 남은 위험을 구분한다. 커밋·Push·MR·병합은 `AGENTS.md`의 사용자 승인 범위를 따른다.

구체적인 명령과 통과 기준은 실제 코드 구조와 실행 환경이 정해진 영역부터 해당 개발 문서에 추가한다. 아직 정해지지 않은 명령이나 테스트 범위를 AI가 임의로 완료 조건으로 확정하지 않는다.

## 도구의 예정 역할

| 도구 | 개발 흐름에서의 역할 | 현재 상태 |
| --- | --- | --- |
| Context7 | 저장소 버전에 맞는 외부 라이브러리·프레임워크 공식 문서 확인 | 설치 조건과 조회 품질 검증 전 |
| Superpowers | 계획·구현·검증·리뷰 흐름을 보조하는 기본 기능 확인 | 기본 기능과 RunWay 적용 범위 검증 전 |
| Maestro MCP | 모바일 앱의 주요 화면과 사용자 흐름 Smoke Test | 설치·연결과 대상 시나리오 검증 전 |

도구가 제안하는 절차나 외부 문서는 RunWay의 요구사항·계약·작업 규칙보다 우선하지 않는다. 도구 간 조합과 오케스트레이션은 각각의 검증 결과를 확인한 뒤 별도 업무에서 결정한다.

## 현재 확정된 범위

- Context7, Superpowers, Maestro MCP를 개발 및 검증 도구로 활용할 계획이다.
- 기존 FEELM 프로젝트의 AI 관련 Markdown 문서를 참고해 RunWay의 AI 작업 규칙을 관리한다.
- 실제 공통 작업 규칙과 인증정보 보호 기준은 저장소 루트의 [`AGENTS.md`](../../../AGENTS.md)를 기준으로 한다.

## 아직 확정하지 않는 항목

- 도구별 테스트 범위와 통과 기준
- 다른 AI 도구와의 조합 및 오케스트레이션 방식
- RunWay 서비스 내부 AI 모델·에이전트 구성과 프레임워크
- 개발용 Subagents의 역할과 운영 방식
- Skills, Hooks, CI의 구체적인 구성
- 테스트 및 배포 아키텍처

위 항목은 조사·비교 결과와 선행 결정을 바탕으로 별도 업무에서 확정한다. 합의 전에는 설정 파일이나 실행 구조를 만들지 않는다.
