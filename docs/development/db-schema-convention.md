# 물리 스키마 규칙과 마이그레이션 정책

> 상태: 작성 틀만 준비 · ERD 변경 정리 후 세부 규칙 작성

DB 구조와 변경 이력의 관리 기준을 정리할 문서다. 현재 ERD를 변경 중이므로 테이블·컬럼·타입·
제약·인덱스 규칙과 마이그레이션 운영 절차를 이 문서에서 새로 확정하지 않는다.
아래 작성 항목은 구현 지시나 확정된 계약이 아니다.

## 1. 이미 결정된 기준

- DB 접근 기술: [Spring Data JPA](../adr/0008-spring-data-jpa.md)
- DB 구조 변경 이력 관리: [Flyway](../adr/0009-flyway-schema-migrations.md)
- 현재 합의된 매핑·DB 변경 원칙: [백엔드 컨벤션 6장](backend-convention.md#6-entity와-스키마-매핑)

위 결정은 유지한다. ERD 변경을 마친 뒤 해당 데이터 모델에 맞는 세부 규칙과 초기 구성을 정한다.
기술 선택이 실제 DB 구성이나 마이그레이션 적용 완료를 뜻하지 않는다.

## 2. 이후 작성할 항목

| 항목 | 작성할 내용 | 상태 |
| --- | --- | --- |
| 이름 | 테이블·컬럼·제약·인덱스 명명 규칙 | 작성 대기 |
| 식별자와 타입 | 기본키·외래키, 시각·날짜·수치·공간 데이터 매핑 | 작성 대기 |
| NULL과 기본값 | 결측값·필수값·상태·감사 컬럼 처리 | 작성 대기 |
| 관계와 삭제 | 외래키·삭제 정책과 데이터 보존 기준 | 작성 대기 |
| 제약과 인덱스 | 유일성·값 범위·조회 목적별 인덱스 기준 | 작성 대기 |
| DB 확장 | 확장 기능의 설치·권한·적용 책임 | 작성 대기 |
| 변경 파일 | Flyway 파일 위치·이름·번호와 병렬 작업 충돌 처리 | 작성 대기 |
| 적용과 복구 | 환경별 실행 시점·기존 DB 처리·실패 대응 | 작성 대기 |
| 검증 | 초기 생성·기존 데이터 보존·변경 적용 테스트 | 작성 대기 |

## 3. 작성 재개 시 확인

- 변경이 정리된 [ERD](../design/db/erd.md)와 [기준 스키마](../design/db/schema.sql)의 합의 상태
- 실제 사용할 DB 환경과 버전, 기존 DB·보존할 데이터 유무
- 관련 API 계약 및 도메인·공통 기반 담당 범위

이 문서를 채우기 위해 ERD·스키마를 임의 변경하거나 초기 SQL·마이그레이션 파일을 먼저 만들지 않는다.
작성 시점의 최신 합의 내용을 확인하고, 기존 문서와 충돌하면 먼저 조정한다.
