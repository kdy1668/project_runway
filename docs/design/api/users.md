## U01 로그인

`POST` `/api/v1/auth/login`

| 항목 | 값 |
|---|---|
| 단계 | 1차 MVP |
| 인증 | 공개 |
| 관련 요구사항 | USR-001 / SYS-002 |
| 관련 화면 | 1.1 시작, 1.2 로그인 (화면 설계 v10) |
| 미정 사항 | 있음 |
| 비고 | API 요청/응답 필드와 값 제한은 검토용 제안 |

### 설명

아이디·비밀번호로 로그인한다. 계정 생성은 [U15 회원가입](#u15-회원가입)으로 분리했다.

### 인증 및 권한

- 공개 호출. 아이디·비밀번호 일치 여부와 로그인 제한 상태를 검사한다.
- 건강정보·실시간 위치·타인 기록 조회 시 동의 상태 및 공개 범위가 우선한다.

### Path Parameters

없음

### Query Parameters

없음

### Request Body

| 필드 | 타입 | 필수 | 설명 |
|---|---|:---:|---|
| `loginId` | string | O | 로그인 아이디(영문·숫자 4–16자) |
| `password` | string | O | 비밀번호 |

```json
{
  "loginId": "minjun01",
  "password": "********"
}
```

### Response

`200 OK (제안)`

```json
{}
```

응답 필드 정의(상세 객체는 미정 정책 확정 후 보완):

| 필드 | 타입 | 필수 | 설명 |
|---|---|:---:|---|
| `user` | object | X | ERD 및 화면 요구사항을 기준으로 확정 필요 |
| `accessToken` | string / object (확인 필요) | X | ERD 및 화면 요구사항을 기준으로 확정 필요 |
| `refreshToken` | string / object (확인 필요) | X | 갱신 토큰(저장/쿠키 정책 미정) |
| `onboardingCompleted` | boolean | X | 초기 설정(1.4~1.6) 완료 여부. 미완료면 초기 설정 화면으로 이동 |

### 오류 응답

- `401 INVALID_CREDENTIALS` — 아이디 또는 비밀번호 불일치. 남은 시도 횟수(`remainingAttempts`)를 `details`에 포함(제안)
- `429 LOGIN_LOCKED` — 5회 연속 실패 시 10분간 로그인 제한. 해제 시각(`lockedUntil`)을 `details`에 포함(제안)
- 공통 인증 오류 `401 UNAUTHORIZED`, 권한 오류 `403 FORBIDDEN`, 요청 형식 오류 `400 VALIDATION_ERROR` (해당 시).

### 처리 규칙

- 화면 1.2 기준: 연속 5회 실패하면 10분간 로그인을 제한한다(실패 횟수 기준 단위는 아이디별 제안).
- 외부 제공자(소셜) 로그인은 화면 설계 v10 기준 범위에서 제외했다.
- 사용자 소유권·그룹 참가 권한·상태 전이·재요청 여부를 검증한다(적용 범위는 API별로 결정).
- 예시는 **명세 구조를 보여주는 가상 값**이며, 확정되지 않은 제한·동기화 주기·AI 호출 주기를 의미하지 않는다.

### 상태값

- PUBLIC / PRIVATE 또는 기능별 ERD CHECK 값, 해당 없으면 별도 상태 없음.

### 미정 사항

- [ ] 비밀번호 해시 알고리즘, 로그인 실패 횟수 저장 위치·초기화 조건 확정
- [ ] 요청·응답의 세부 필드 타입, 허용 범위, nullable 규칙 및 실제 JSON 구조 검토
- [ ] HTTP 성공 코드 및 각 예외의 오류 코드 최종 확정
- [ ] 접근 권한과 데이터 정합성의 구체적인 처리 조건 확정

## U25 팔로우 요청 승인·거절

### 설명

내 계정에 들어온 특정 팔로우 요청을 승인하거나 거절한다.

### 인증 및 권한

- 본인 계정에 들어온 요청만 조회·처리한다. 다른 계정의 요청은 처리할 수 없다.

### Path Parameters

| 필드 | 타입 | 필수 | 설명 |
|---|---|:---:|---|

없음

### Request Body

```json
{
  "decision": "APPROVE"
}
```

### Response

`200 OK (제안)`

```json
{
  "requesterId": "00000000-0000-4000-8000-000000000001",
  "followStatus": "FOLLOWING"
}
```

### 오류 응답

- `401 UNAUTHORIZED`
- `404 REQUEST_NOT_FOUND`
- `409 REQUEST_STATE_CONFLICT`
- `422 INVALID_DECISION`

### 처리 규칙

- 승인 확정 후 요청자에게 팔로우 승인 알림을 자동 연계한다. 거절 알림과 묶음·전달 방식은 [알림 정책](../requirements.md#알림-정책)의 제안·미정 항목을 따른다.

- `decision`은 APPROVE 또는 REJECT다. 대상 계정 소유자만 결정할 수 있다.
- 승인 시 팔로우 관계를 확정하고 팔로워 수와 비공개 프로필·게시물 접근 권한을 반영한다. 거절 시 접근 권한을 부여하지 않으며 `followStatus=NONE`을 반환한다.
- 같은 결정 재전송은 멱등 처리한다. 요청 취소·반대 결정·계정 공개 전환과 경합할 때 오래된 승인 요청이 관계를 되살리지 않도록 상태를 검사한다.
- 요청 기록 보관·재요청 세대 식별과 이미 처리한 요청의 응답 정책은 세부 설계에서 확정한다.

### 상태값

PENDING → 승인 FOLLOWING / 거절 NONE. 내부 요청 이력 상태는 ERD 검토 대상.

### 미정 사항

- [ ] 거절 후 재요청 제한·요청 이력 수명·경합 및 재전송 판별
- [ ] 승인·거절 및 공개 전환 자동 승인 결과 알림 방식

## 계정 공개 정책의 공통 적용 범위

- 피드·검색·프로필·게시물 상세·댓글·반응·공유 결과·이미지 참조 모두 계정 접근 정책을 적용한다. 목록 필터만으로 보호하지 않는다.
- 프로필의 월 요약·최근 공유 게시물도 동일한 권한을 따른다. 원본 H02 조회로 타인 기록을 우회 열람시키지 않는다.
- 계정 전환·팔로우 취소·승인·거절 시 접근 권한과 캐시·이미지 접근을 함께 반영한다.
- 기존 ERD의 프로필·세션·위치 공개 필드, 게시물 공개 필드와 팔로우 관계의 대기·승인 모델은 별도 수정·검증 대상이다. 이번 API 문서 수정으로 실제 DB 계약을 변경하지 않는다.
- 공용 코스 이름과 개인 북마크 별명도 별도 데이터 모델 검토 대상이다. 별명은 사용자와 코스의 저장 관계에만 두고 공개하지 않는다.
